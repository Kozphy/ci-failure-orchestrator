# Commercial experiments

No experiment below has been run. Counts are zero. Do not fill them from memory or from a compliment.

## Experiment A — problem validation

Target: 10 developers or engineering managers who run GitHub Actions. A qualified person has shipped code in the last month and can describe a CI failure without being coached.

Ask:

- How often does a failing workflow stop your work?
- Which kinds of failures take the longest to understand?
- What do you use today to read those logs?
- What is missing in that tool?
- Would a written diagnosis with the log line and a recommended command change the next step you take?
- Which permission would stop you from installing a read-only Action?

Record the answer. A positive adjective is not purchase intent.

## Experiment B — product activation

Target: 5 people who are not the author.

Measure, with denominators:

- Installation completion: people who merged a workflow calling the Action, divided by people who tried.
- First diagnosis: steps that finished with `diagnosis-status=diagnosed`, divided by completed installations.
- Time to first diagnosis: minutes from the workflow file being added to the first successful job. Median only after at least three timings.
- Setup failures: jobs that failed before a report existed.
- Useful versus rejected recommendations: the user's label, not ours.
- Repeat use: a second run in a later week.
